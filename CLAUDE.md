## What this repo is

Two GitHub Pages dashboards tracking VOD delivery for Frndly TV / Roku Programming Ops. Each dashboard compares what a vendor claims to have sent (Airtable export) against what the CMS has actually received (daily email report compiled in Excel).

- `index.html` — UpFaithVOD dashboard
- `roku-originals.html` — RokuOriginals dashboard

The HTML files are fully self-contained (inline CSS + JS). They are generated by Python scripts and should not be edited directly.

## Running the scripts

Both scripts live outside the repo on the local machine. Run from any directory:

```bash
python3 ~/Downloads/vod_check.py             # UpFaithVOD → index.html
python3 ~/Downloads/roku_originals_check.py  # RokuOriginals → roku-originals.html
```

Each script loads data, renders HTML to `~/vod-dashboard/`, commits, and pushes to GitHub Pages automatically.

| `VOD_Report_Cumulative.xlsx` | Daily VOD email (header row 1, data starts row 2) | both scripts |

**Daily update steps:**
1. Paste new VOD email rows into `VOD_Report_Cumulative.xlsx` at the bottom (no header — data rows only)
2. Re-download the relevant Airtable CSV(s) if vendor data has changed
3. Run the script(s)

## How CMS matching works

**UpFaithVOD (`vod_check.py`):**
- Filters VOD Report to rows where `Content Partner` contains `upfaithvod` (case-insensitive)
- Movies: matches on `title` (lowercase) vs `Video/Movie Name`
- Episodes: matches on `(series_name, title)` tuple first, then falls back to title-only match
- `vendor_sent` = `direct_s3_timestamp` is not null

**RokuOriginals (`roku_originals_check.py`):**
- Filters VOD Report to rows where `Content Partner` == `RokuOriginals` (exact)
- Excludes Airtable rows with `DELIVERY STATUS` == `8. Do Not Send`
- `vendor_sent` = status is in `{'5. Delivery Complete', '9. Re-Delivery Complete'}`
- Matches on `ep_title` (lowercase) vs `Video/Movie Name` only — no series cross-check
- Series name is extracted from the `Name` field by stripping trailing episode/season codes via regex
